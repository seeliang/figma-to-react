figma-to-react · theme

From Swatch to Token

Colours, typefaces and spacing, from a Figma file to a tested theme. One command with modes, matched to the stages of delivery.

Stage Run
00 Design Ready pnpm ds:theme --audit
01 Generate pnpm ds:theme
02 Test pnpm --filter figma-to-react-example test-storybook
03 Review pnpm ds:theme --diff
04 QA signoff pnpm verify
— Release NX and CI, outside this repo

What each one does

  • 00

    Design Ready

    Asks whether the Figma file is ready to generate a theme from. Right now every colour is unbound, so all eight token names are derived from the values rather than chosen by a designer. Bind a Colour Style and the derived name is never used again — which is why this stage comes first, and not after you have versioned those names.

  • 01

    Generate

    Writes four files from one pass: tokens.css for browsers, tokens.json as data, fonts.css to load the typefaces, and theme.stories.tsx — every token as a swatch. Add --offline to work from the recorded response; the Figma quota is set by plan tier and runs out fast.

  • 02

    Test

    The test is generated with the story, so the design decides how many assertions there are: seven colours in Figma means seven checked values, and an eighth is covered the moment it exists. It checks the count before any value — a token with no swatch at all is the failure a per-swatch loop skips over silently.

  • 03

    Review

    Prints what would be added, removed or changed against the committed tokens. Offline, so checking costs nothing. This is what belongs in a pull request description.

  • 04

    QA signoff

    Three checks, each where it is cheapest: the swatch paints its declared value (a real browser), the committed tokens still match Figma (node, no browser), and the naming is stable and collision-free (a pure function). Plus the build, the types and the component fidelity.

The names are ours, not Tailwind's. This design system is hand-tailored. Derived names resemble Tailwind's because they come off a similar ramp, but agreeing with it is not a goal and is never asserted. A derived name describes a colour; it cannot say what the colour is for. That is stage 00's job.

Deeper detail lives with the skills — ds-theme for the stages, references/theme.md for naming and the known token collision. Versioning is deliberately absent here: NX and CI own it, and two answers to one question is worse than none.
