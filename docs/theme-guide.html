The flow

One command with modes, not five commands — the stages share the same config and the same offline decision. --audit and --diff never touch the network.

00

Design Ready — before you generate anything

Bind Colour Styles first, or you are versioning names that are about to change. 

pnpm ds:theme --audit

Every colour in this file is currently unbound, so all eight names are derived from the values themselves. That works, and it is deterministic — but a derived name describes a colour, it cannot say what the colour is for.

Hex Chroma L* Derived name
#2563eb 0.776 46.1 blue-600
#0f172a 0.106 8.0 slate-950
#64748b 0.153 48.3 slate-600
#e2e8f0 0.055 91.8 blue-200

Chroma decides grey against hue, CIE L* places the step. Both are deliberate: HSL saturation calls #0f172a a 47%-saturated blue, which would stand a plain slate next to a genuinely blue blue-600.

These are not Tailwind names, and they are not meant to be. This design system is hand-tailored. The names only resemble Tailwind's because they come off a similar ramp; where they disagree, that is not a bug to fix by recalibrating. Bind a Colour Style and the derived name is never used again — that is the whole of stage 0.

01

Generate

pnpm ds:theme                        # live, from the current Figma file
node scripts/ds.mjs theme --offline  # from the recording; spends no quota

Four files, all out of one collection pass, so they cannot disagree with each other:

tokens.css          the Tailwind @theme block, for browsers
tokens.json         the same tokens as data, for everything else
fonts.css           loads the typefaces the theme names
theme.stories.tsx   every token as a swatch, with its own assertions

Import order is load-bearing. fonts.css must come first — a CSS @import is only valid ahead of every other rule. Put it anywhere else and the bundler drops it silently; the page renders in the fallback typeface and looks fine to whoever built it.

02

Test — generated, so the design decides how many

Seven colours in Figma means seven checked values. An eighth is covered the moment it exists. 

pnpm --filter figma-to-react-example test-storybook

The play function checks the count first, then the values. A token with no swatch is the failure a per-swatch loop skips over silently — and it is also the likeliest, because it means the design gained something the page does not know about.

Both failure modes, run against a deliberately broken build:

1 token(s) do not paint their declared value:
  --color-blue-600  declared #2563eb  painted #ff0000
Usually the theme was not imported, or a later @theme block redeclared the same property.

1 of 7 token(s) have no swatch in the DOM:
  --color-blue-200 (#e2e8f0)

theme.stories.tsx is overwritten on every run. Hand-written stories belong in a *.custom.stories.tsx, which the generator never touches.

03

Review

pnpm ds:theme --diff

Added, removed and changed, against the committed manifest. This is what goes in the PR description. 

Theme changes if regenerated:

  - --color-ghost: #abcdef
  ~ --color-blue-600: #123456 -> #2563eb

Run `pnpm ds:theme` to apply.
04

QA signoff

pnpm verify

Three checks, each living where it is cheapest rather than all in the browser:

Check Where Catches
rendered vs declared theme.stories.tsx a token that never reached the bundle, or was overridden
committed vs Figma verify-tokens.mjs the design moved and nobody regenerated; hand-edited output
stable and unique tokens.test.ts a naming change that would silently rename every token

The first needs a real browser — jsdom will not resolve var(). The second needs the recorded Figma response but no browser, so it runs in CI without Playwright. The third is a pure function and costs nothing.

The third asserts what the naming actually promises: the same colour always yields the same name, and two tokens never share one. Not that the name agrees with anybody else's palette.

What the file is missing

Design issues, each one action in Figma. None can be fixed in code.

62 colours bound to no Style or Variable

All eight token names are derived. This is stage 0, and it is the highest-value change available.

Fix · Select the swatch in Figma and create a Colour Style. Style names come through on every plan; Variable names need Enterprise.

No font sizes bound, so no --text-* entries

Eight distinct type combinations, none bound, so every size is emitted inline as text-[14px].

Fix · Bind font size to a Variable. A Text Style is not enough — the REST API exposes only its colour per node.

No breakpoints anywhere

The theme has colours and spacing but nothing responsive, so no sm: or lg: class is ever generated.

Fix · Add breakpoint variants — a Size or Breakpoint property with Mobile / Tablet / Desktop — to the components that reflow.

--color-blue-600 is declared twice, at different values

The card fixture says #2663eb, the design system says #2563eb, and the design system wins by import order. Two design files synthesising the same name for different colours. verify-tokens.mjs now reports it by name instead of leaving it silent.

Fix · Bind a Colour Style in at least one of them, or keep their themes out of the same stylesheet.

Versioning is NX and CI's job — there is no semver, changelog or release command in this repo, on purpose: two answers to one question is worse than none. Generated names are stable, so git diff on the output is a signal about the design rather than noise about the generator.
